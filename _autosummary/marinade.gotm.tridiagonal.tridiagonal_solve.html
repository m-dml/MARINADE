tridiagonal_solve¶

marinade.gotm.tridiagonal.tridiagonal_solve(a: torch.Tensor, b: torch.Tensor, c: torch.Tensor, y: torch.Tensor, method: str = 'thomas', implicit_backward: bool = True) → torch.Tensor[source]¶

Solves a batch of tridiagonal systems \(A x = y\) with the chosen algorithm.

Parameters:

  • a (torch.Tensor) – Lower diagonal of A. [batch_size, (1 or n_rhs), n_rows - 1]

  • b (torch.Tensor) – Main diagonal of A. [batch_size, (1 or n_rhs), n_rows]

  • c (torch.Tensor) – Upper diagonal of A. [batch_size, (1 or n_rhs), n_rows - 1]

  • y (torch.Tensor) – Right-hand side vector. [batch_size, n_rhs, n_rows]

  • method (str) – Algorithm used to solve the linear system. One of (“thomas”, “paracr”, “linalg”). Defaults to “thomas”.

  • implicit_backward (bool) – if True, uses custom backward method based on implicit differentiation. This allows us to discard intermediate calculations and backpropagate gradients from x to a, b, c and y based only on the inputs and outputs. To achieve this, we solve another linear system on the backward pass, whose l.h.s. is the tranpose of A. If False, we’ll solve the system with standard torch(script) operators, and the backward pass will differentiate through every step of the tridiagonal solver algorithm. In this case all intermediate computations must be stored on the computation graph.

A is n_rows x n_rows. n_rhs is the number of right-hand-side vectors y for each batch element. The coefficients a,b,c of the linear system can be common (broadcasted) across r.h.s. vectors, or not.

Assumes n_rows > 2.

Returns:

Solution x. [batch_size, n_rhs, n_rows]
